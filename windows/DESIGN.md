# Windows 编辑器界面

本轮直接参考微软 2026-10-15 公布的 **WinUI 3 Photos Editor** 官方截图。该版本从 Windows Insider 开始推出，和此前 Photos 编辑器的布局不同。

参考：[Meet the new Photos app on Windows 11](https://blogs.windows.com/windowsexperience/2026/10/15/meet-the-new-photos-app-on-windows-11/)；[官方 Editor 截图](https://blogs.windows.com/wp-content/uploads/sites/2/2026/10/The-all-new-native-Editor-1024x654.jpg)。

## 对应关系

| Photos Editor 的结构 | 码住的实现 |
| --- | --- |
| 单行顶栏：历史命令、文件名、保存 | 左侧导入／粘贴／历史命令，中部文件名，右侧确认与导出 |
| 照片优先的画布 | Mica Alt 作为编辑器背景，画布置于圆角容器，图片和光标均裁切在容器内 |
| 右侧独立工具面板 | 292 px 面板，顶部五种打码工具，下方为当前工具参数 |
| 工具类别的图标、文字、细下划线 | 原生 ToggleButton 的专用模板，保留键盘与自动化语义，使用完整的 CommonStates |
| 底部尺寸和缩放控件 | 左侧图片尺寸、批次导航，右侧适应窗口、百分比、缩放滑杆 |
| 编辑时没有常驻图片库 | 图片列表默认关闭，点击顶栏按钮以普通内联侧栏展开并推开画布 |

码住保留批量打码的确认、切图和批量导出，不添加 Photos 的裁剪、调色或 AI 功能。底部缩放滑杆采用以 100% 为中心的对数刻度，滚轮仍以指针为锚点缩放。

## 原生交互

- WinUI TitleBar 管理系统按钮与交互区域，使用 Tall 系统标题栏。顶栏、底栏统一为 48 DIP，命令按钮为 32 DIP 并垂直居中。标题栏命令位于 LeftHeader / RightHeader 中。
- 控件颜色来自 ThemeResource，默认跟随系统主题；窗口按钮同步实际主题。
- Inspector 只显示当前工具需要的参数。切换工具会取消尚未提交的笔画。
- 画布区域可用宽度 ≥ 880 px：右侧面板默认常驻，可通过顶栏按钮收起。
- 更窄窗口：右侧以覆盖面板打开。图片列表始终以内联侧栏按需展开，切图后保持展开；可用宽度扣除图片列表后再决定右侧面板布局。
- 宽度 < 1100 px：确认按钮只显示图标，保留完整可访问性名称和工具提示。
- 宽度 < 760 px：隐藏连续缩放滑杆，保留适应窗口、百分比菜单、放大／缩小按钮。
- 最小窗口尺寸约为 640 × 480；初始尺寸按显示器缩放与工作区计算。
- 图片列表使用透明背景融入主界面；缩略图不带底框，保持原比例，最长边为 56 DIP。文件名与尺寸、状态采用两行排版。
- 工具卡片上下与画布区域齐平，两侧各留 12 DIP；画布与卡片之间的间距和卡片右侧边距相同。
- 画布容器与工具卡片共用编辑区的完整高度，圆角为 6 DIP；使用 Composition 圆角裁切，放大后的图片不会盖过容器边缘。
- 画布内用原生 AcrylicBrush 显示半透明圆形笔刷光标，使用单层细描边；直径按窗口逻辑像素计量，随参数滑杆和快捷键更新，缩放图片不改变新笔刷的屏幕大小。落笔时换算为原图坐标，已提交笔画随图片缩放。圈选工具使用十字指针，绘制时显示实线路径和返回起点的闭合虚线；右键或中键平移时使用手形指针。关闭透明效果时使用半透明后备色。
- Mica Alt 保留为窗口背景材质；局部透明光标使用 [WinUI 原生应用内 Acrylic](https://learn.microsoft.com/windows/apps/develop/ui/in-app-acrylic)，不会写入导出的图片。
- 处理提示只覆盖圆角画布容器，侧栏和顶栏不整体禁用或变灰。切图请求排队合并为最新选择，避免快速点击时图片与笔画错配。
- 顶底栏共用高度资源。底栏文字去掉固定行高，使用 Tight 字形边界在 32 DIP 控件行内居中；关闭的提示条不参与布局。工具卡片不再用描边内缩背景。
- 图片列表直接从编辑区顶部开始，不显示标题、确认总数或进度条。Ctrl 点击增减选择，Shift 点击选择连续范围，从空白处拖动框选；Ctrl 框选保留已有选择。
- 拖动图片可调整顺序；多选后拖动其中一张，将整组选项按原相对顺序移动。插入线指示目标位置，Esc 或拖出侧栏取消。顺序立即保存，底栏张数和后续切图采用新顺序，编辑中的图片保持不变。
- 顶栏命令与窗口按钮间保留 8 DIP 左右空隙，并将系统按钮的物理像素占位转换为 DIP，避免高 DPI 下出现额外空白。
- 顶栏图标按钮为 32 DIP，图标为 20 DIP，内边距为 4 DIP，给笔画与抗锯齿留出空间；亮色模式单独检查裁切。
- 工具类别使用一根共享的下划线，通过 180 ms EaseOut 平移到当前工具；快速切换时从当前位置继续，关闭系统动画时直接定位。
- 左侧图片列表和画布不重复叠加水平间距，选中项背景距窗口左侧和画布均为 12 DIP。
- 空工作区提供导入、粘贴入口，隐藏无作用的工具面板与画布底栏。

## 视觉检查

使用发布目录的 Mazhu.exe，传入 --ui-checks --dark 或 --ui-checks --light。追加 --narrow 检查 720 px 窗口，追加 --empty 检查空工作区；--slow-load 在测试切图时增加延迟，用于检查局部加载与连续切图，不影响普通运行。

追加 --layout-checks，在该临时工作区的 layout.json 中每秒记录实际布局尺寸、选中图片、当前编辑图片和列表顺序，核对栏高、文字中轴、工具卡片边界及排序。

使用 --ui-checks --slow-load --workflow-checks 自动检查局部加载范围、页面未被整体禁用、最后一次切图请求、笔刷固定屏幕尺寸、画布和卡片等高等距；完成后退出，并在工作目录写入 workflow-checks-result.txt。可以追加 --light 检查亮色模式，否则使用暗色模式。

检查模式仅在系统临时目录新建 Mazhu-ui-<GUID> 工作区，生成三张示例 PNG；不读取或写入日常工作区，不争用正常实例的互斥锁。示例不包含真实个人数据。临时记录保留以核对笔画、确认与导出结果。

原生实现参考：[TitleBar](https://learn.microsoft.com/windows/apps/develop/ui/controls/title-bar)、[Mica](https://learn.microsoft.com/windows/apps/design/style/mica)、[字体](https://learn.microsoft.com/windows/apps/design/style/typography)。工具图标来自微软 Fluent UI System Icons，许可见仓库 NOTICE.md。
